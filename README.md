# Crack UBIS Memory — 프로토타입

크랙 대화 원문을 작은 구간으로 나누고, 현재 장면과 겹치는 과거 구간을 로컬 규칙으로 찾는 탬퍼몽키 실험입니다. 별도 AI API·서버·모델 다운로드는 없습니다. 대화 읽기와 주입 저장에는 **크랙 자체 서버**를 사용합니다. [전체 기획](PLAN.md)에서 자동 기억과 프리셋의 범위를 볼 수 있습니다.

## 사용

1. `node build.mjs`로 `dist/crack-ubis-memory.user.js`를 만듭니다.
2. 탬퍼몽키에 그 파일을 설치하고 크랙 채팅방을 엽니다.
3. **기억 검색 → 현재 장면 후보 보기**로 검색 결과와 원문 메시지 ID를 봅니다.
4. 실험할 방에서만 **다음 전송부터 자동 적용**을 켭니다. 이후 전송·재생성 직전에 과거 대화 후보를 다시 찾고, 엄격한 기준을 통과한 구간만 이전 AI 답변에 붙입니다. 서버에서 적용을 재조회한 다음 전송을 진행합니다.

적용이 불확실하거나 다른 확장 프로그램의 주입이 보이면 해당 전송을 보류합니다. 입력이 화면에서 사라졌다면 **보류된 입력 복사** 버튼으로 되찾을 수 있습니다. 자동 적용은 기본적으로 꺼져 있습니다. 위시 RP 매니저의 주입과 동시에 사용하지 마세요.

## 현재 범위

- 페이지를 연 상태에서 크랙의 최대 2,000개 메시지를 읽어 **메모리에서 색인**합니다. 페이지를 다시 열면 다시 가져옵니다. 서버 외의 별도 저장소에 대화 원문을 복제하지 않습니다.
- 한국어 두 글자 조각·영문 단어와 희귀 표현을 이용합니다. 검색 후보와 실제 자동 적용 기준은 분리돼 있습니다. 애매하면 넣지 않습니다.
- 지난 대화를 사실로 새로 요약하지 않습니다. 당시 원문을 출처와 함께 넣습니다.
- 유저노트·페르소나 프리셋은 아직 포함하지 않았습니다.
- 크랙 로그인 계정에서의 동작, 긴 방의 응답 시간, 최종 모델 입력 반영은 **아직 검증되지 않았습니다**. 비공식 API·웹소켓 흐름이 바뀌면 동작하지 않을 수 있습니다.

## 개발 확인

```sh
node build.mjs
node --check dist/crack-ubis-memory.user.js
node --test test/engine.test.mjs
```

검색 구조는 UBIS의 원문 증거·작은 단위·복수 신호·출처 표시 방식을 응용했지만 UBIS Rust 코드를 브라우저에 이식한 것은 아닙니다. 위시 코드를 복사하지 않은 독립 실험입니다.
