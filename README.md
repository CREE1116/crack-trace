# Crack UBIS Memory — 프로토타입

크랙 대화 원문을 로컬에서 검색해 관련 과거 메시지 발췌를 **현재 사용자 입력 앞에 붙이는** 탬퍼몽키 실험입니다. 별도 AI API·서버·모델 다운로드는 없습니다. 대화 읽기와 전송에는 **크랙 자체 서버**를 사용합니다. [전체 기획](PLAN.md)에서 자동 기억과 프리셋의 범위를 볼 수 있습니다.

## 사용

1. `node build.mjs`로 `dist/crack-ubis-memory.user.js`를 만듭니다.
2. 탬퍼몽키에 그 파일을 설치하고 크랙 채팅방을 엽니다.
3. **기억 검색 → 현재 장면 후보 보기**로 검색 결과와 전송될 문맥을 봅니다.
4. 실험할 방에서만 **다음 전송부터 입력 앞에 붙이기**를 켭니다. 사용자 메시지를 전송할 때 희귀한 표현이 겹치는 과거 메시지와 세부 조각을 JSON 기억 캐시로 묶어 앞에 붙입니다. 지시문·캐시·원래 입력 전체는 2,000자 이내로 제한합니다. 원래 입력은 끝에 그대로 둡니다.

이 방식은 서버에 저장되는 **사용자 메시지 자체를 바꿉니다.** 주입문이 채팅 화면에도 보일 수 있습니다. 재생성에는 적용하지 않습니다. 전송 준비 중 오류가 나면 전송을 보류하고 원래 입력을 복사할 수 있게 합니다. 기본적으로 꺼져 있는 실험 기능이며, 이전 버전의 자동 적용 설정은 이어받지 않습니다. 크랙 실계정에서 최종 모델 반영은 아직 확인하지 않았습니다. [평가 결과](REPORT.md)를 먼저 확인하세요.

## 현재 범위

- 페이지를 연 상태에서 크랙의 최대 2,000개 메시지를 읽어 **메모리에서 색인**합니다. 페이지를 다시 열면 다시 가져옵니다. 서버 외의 별도 저장소에 대화 원문을 복제하지 않습니다.
- 한국어 두 글자 조각·영문 단어로 후보를 찾고, 희귀한 단어 일치가 있는 메시지만 입력 후보로 씁니다. 검색 결과는 메시지별로 묶어 원문 전체를 펼칠 수 있습니다.
- 짧고 단서가 부족한 후속 입력에서는 직전 사용자·AI 메시지 양쪽에 나온 드문 단어를 검색어에 최대 3개 보탭니다. 실제 전송할 사용자 문장은 바꾸지 않습니다.
- 지난 대화를 사실로 새로 요약하지 않습니다. 상위 메시지의 앞부분을 먼저 넣고 예산이 남으면 검색에 걸린 세부 조각을 최대 8개 기록까지 더합니다. JSON에는 출처 메시지·화자·조각 종류·원문을 적고, 크랙 모델에 이를 RP 대사나 지시가 아닌 기억 자료로 취급하라고 명시합니다. 형식만으로 모델의 준수를 보장하지는 않습니다.
- 유저노트·페르소나 프리셋은 아직 포함하지 않았습니다.
- 크랙 로그인 계정에서의 동작, 긴 방의 응답 시간, 최종 모델 입력 반영은 **아직 검증되지 않았습니다**. 비공식 API·웹소켓 흐름이 바뀌면 동작하지 않을 수 있습니다.

## 개발 확인

```sh
node build.mjs
node --check dist/crack-ubis-memory.user.js
node --test test/engine.test.mjs
node --test test/export.test.mjs
```

크랙 텍스트 내보내기를 로컬에서 평가할 때는 `node tools/evaluate-export.mjs /path/to/chat.txt`를 실행합니다. 기본 출력은 집계만 표시하며, `--details`를 붙이면 과거 기준의 선택 메시지 번호와 일치 단어도 표시합니다. 원문은 레포에 복사하지 않습니다. 이 평가는 입력에 과거 원문이 포함됐는지만 확인하며, 크랙 모델이 실제로 기억을 활용했는지는 판정하지 않습니다.

답이 있는 회상 질문을 평가할 때는 `node tools/benchmark-export.mjs /path/to/chat.txt /path/to/private-cases.json`을 실행합니다. 사례 파일 형식은 `[{"id":"case-1","query":"질문","evidence":[{"message":12,"contains":"답을 담은 원문 일부"}]}]`입니다. 개인 대화에서 만든 사례 파일은 레포에 넣지 않습니다.

검색 구조는 UBIS의 원문 증거·작은 단위·복수 신호·출처 표시 방식을 응용했지만 UBIS Rust 코드를 브라우저에 이식한 것은 아닙니다. 위시 코드를 복사하지 않은 독립 실험입니다.

2,000자는 주입 예산 가정입니다. 크랙의 과금 구간이 같다는 공식 근거는 확인하지 못했습니다.
